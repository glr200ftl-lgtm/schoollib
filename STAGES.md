# Этапы проекта

## Готово

### Этап 1 — Каркас проекта, схема БД, демо-данные ✅
- Стек зафиксирован: Python 3.12 + Django 5.x + PostgreSQL 16 (dev — SQLite через `DATABASE_URL=sqlite`).
- Модели и миграции: `users`, `categories`, `books`, `ads` (поля по ТЗ п.6).
- Layout: шапка (логотип, меню Главная/Каталог/Обмен), футер (контакты школы).
- Seed: `python manage.py seed_demo` — 3 пользователя, 6 категорий, 12 книг
  с обложками-заглушками (Pillow), 3 объявления; идемпотентен.
- Заглушки страниц: `/`, `/catalog/`, `/exchange/` (200, общий layout).
- README.md с командами установки/запуска.

### Этап 2 — Аутентификация и роли ✅
- Приложение `accounts`: регистрация (ФИО, e-mail, пароль ×2, класс), вход/выход,
  восстановление пароля, страница профиля (`/my/`): правка ФИО/класса/контакта, смена пароля.
- Подтверждение e-mail: токен-ссылка; в dev письмо выводится в консоль (`[MAIL]`).
- Дубли e-mail отклоняются с понятной ошибкой; пароли хранятся хешем (pbkdf2_sha256).
- Роли guest/student/admin + middleware (`accounts/access.py`): гость на `/my/` → редирект
  на вход; ученик на `/admin/` → 403; заблокированный (`is_blocked`) не может войти.
- Тесты: `python manage.py test accounts catalog` (19 тестов).

### Этап 3 — Публичный каталог и поиск ✅
- `/catalog/`: сетка карточек, пагинация 24/стр, фильтр по категориям со счётчиками.
- `/catalog/<id>/`: книги категории + счётчик.
- `/book/<id>/`: обложка (заглушка «Нет обложки»), название, автор, категория,
  каталожный номер (`ШК-ГГГГ-NNNN`, уникальный), год, описание, статус наличия.
- Поиск `?q=` по названию И автору, частичное совпадение, регистронезависимо
  (`__lower__contains` — одинаково на SQLite и PostgreSQL); результат со счётчиком,
  пустое состояние «Ничего не найдено»; фильтр и поиск комбинируются.
- Миграция `0002` добавляет `catalog_number`, `year` (+ data-миграция для seed-книг).

### Этап 4 — Доска объявлений и личный кабинет ученика ✅
- `/exchange/`: лента только активных объявлений незаблокированных пользователей;
  фильтры «Отдам / Ищу / Обменяю», поиск по названию, пагинация.
- `/exchange/<id>/`: карточка объявления (все поля ТЗ п.3.3.1), до 3 фото.
- `/my/ads/`: свои объявления со статусами; форма создания/редактирования
  (название, автор, тип, описание, до 3 фото с валидацией типа/размера,
  контакт по умолчанию из профиля, статус); редактирование/удаление/архивация —
  только своих (чужие → 403). Гость видит ленту и карточки, кнопка «Создать» — только ученику.

### Этап 5 — ЛК администратора: ручное управление каталогом ✅
- `/admin/books/`: таблица книг (обложка, название, автор, категория, кат. номер),
  поиск, фильтр по категории, пагинация; добавление/редактирование
  (`/admin/books/add`, `/admin/books/<id>/edit`) с загрузкой обложки с компьютера;
  удаление с подтверждением (`/admin/books/<id>/delete`).
- `/admin/categories/`: создать, переименовать, удалить (непустая — запрещено, 400).
- Боковое меню админки: пункты следующих этапов — заглушки «скоро».
- Права: гость → редирект на вход, ученик → 403 на всех `/admin/*`;
  дубль каталожного номера отклоняется с ошибкой формы; обложка > 5 МБ или
  не-изображение отклоняется с понятным сообщением (FileField + clean_cover).

### Этап 6 — CSV-импорт и экспорт каталога ✅
- `/admin/import`: drag&drop + кнопка; автоопределение разделителя (`;`/`,`) и
  кодировки (UTF-8 / UTF-8 BOM); режимы «добавить новые» и upsert по `catalog_number`;
  предпросмотр-сводка («добавлено N, обновлено M, ошибок K») без записи в БД (dry-run);
  построчный отчёт ошибок (номер строки CSV + причина), корректные строки импортируются;
  обложки по URL из колонки `cover` либо по имени файла из ZIP, загруженного вместе с CSV;
  отсутствующие категории создаются автоматически.
- `/admin/export`: выгрузка всей базы или отфильтрованной выборки (`?q=`, `?category=`);
  UTF-8 с BOM; колонки = колонкам импорта (round-trip: экспорт → правка → импорт).
- Модуль `catalog/csv_io.py`; тесты `catalog/tests_csv.py`.
